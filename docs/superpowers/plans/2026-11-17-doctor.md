# Doctor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `repeat-o-scope doctor` checks your Claude Code config against the gist's checklist and says what to change.

**Architecture:**
- A new module `doctor.py` reads config files only, never transcripts, and returns one `Check` per item of the checklist.
- Settings come from the user, project and local `settings.json` files. For each key, the highest-precedence file that sets it wins, and the check names that file.
- Rendering follows `measure`: no `--format` prints a rich table, `--format markdown` and `--format json` give agents plain text. Failing checks come first.
- No check needs classification: the CLAUDE.md rules are matched with regexes. So there is no `--jev`, and Google's decisions API and Clef aren't needed here (see Open question 6).

**Tech Stack:** Python 3.12+, stdlib, existing `fire` and `rich`. pytest. uv.

**Spec:** `docs/superpowers/specs/2026-11-17-budget-audit-design.md` (step 2, Audit settings). The checklist and the fix wording come from `docs/why.md`.

## Open questions for Kimmo (the plan picks the default shown)

1. **Which settings files.** Default: `~/.claude/settings.json` (user), `<cwd>/.claude/settings.json` (project), `<cwd>/.claude/settings.local.json` (local); local beats project beats user. Managed settings (`C:\Program Files\ClaudeCode\managed-settings.json`) are not read.
2. **Where effort lives.** Your settings have `modelSettings."claude-opus-5-5".effortLevel`, keyed by the full model id while `model` is the alias `opus`. Default: collect every `modelSettings.*.effortLevel` plus a top-level `effortLevel`. The check passes when all of them are `low` or `medium`. Not set anywhere fails, because the gist says to set it.
3. **What counts as an enabled skill.** Default: `SKILL.md` files under `~/.claude/skills/*/`, `<cwd>/.claude/skills/*/`, and `skills/*/` of each plugin that `enabledPlugins` has as `true`, at the `installPath` in `~/.claude/plugins/installed_plugins.json`; minus the names `skillOverrides` turns `off`. An override key matches the bare skill name or `plugin:skill`. Built-in and claude.ai skills aren't on disk, so the row says "at least N". The check fails above 30 (`_MAX_SKILLS`, the one switch); the gist gives no number.
4. **Status line.** Default: passes when `statusLine.command` is set. Doctor does not read the script to check that it shows context % and usage %.
5. **Detecting the rules in CLAUDE.md.** Files: `~/.claude/CLAUDE.md`, `<cwd>/CLAUDE.md`, `<cwd>/.claude/CLAUDE.md`. Default regexes, case-insensitive:
   - scope rule: `whole scope|out of scope|\(OOS\)`
   - read-once rule: `read,? edit,? read,? edit|read (?:\w+ ){0,3}once|in one pass`

   Both match your CLAUDE.md and the gist's wording.
6. **Classification.** Default: none, as above. If you want a model to judge the CLAUDE.md rules instead of regexes, the Jev/Gemini/Clef research comes first, and that's a separate plan.
7. **Exit code.** Default: always 0. Doctor is advice, not a gate.
8. **Base branch.** `format=None` (the rich-table default) is in PR #10, not on `main`. Default: rebase `doctor` onto `measure` now, and onto `main` once #10 is merged. The alternative is to copy #10's `format` change here and resolve the conflict later.

## Global Constraints

- Checks, in this order everywhere (`doctor.CHECKS`): `effort`, `skill_overrides`, `skills`, `status_line`, `scope_rule`, `read_once_rule`.
- Rows sort failing first, then in `CHECKS` order (the gist calls effort "the biggest lever").
- Doctor reads config, not transcripts. Out of scope: `compare` and baselines (step 4), the skill drafting fixes (step 3), and the gist's other settings (MCP loading, `permissions`, hooks, memory).
- Doctor never writes a file and never prints a settings value it doesn't check: `env` and `mcpServers` hold secrets.
- No `--format` prints a rich table. `markdown` and `json` are plain text. Any other value raises the same `RepeatOScopeError` as `measure`.
- Python `>=3.12`, no new dependencies. Repo rules: keyword-only arguments for 2+ parameters, private helpers, `_LOGGER`, `RepeatOScopeError` with the offending value in the message, negative tests first, tests through real-shaped files in `tmp_path`.
- Work in `.wt/doctor` on branch `doctor`. Run git from inside it, never `git -C`. Commit freely. Never push.

## Review Focus

1. **A fresh install**: no `~/.claude/settings.json`, no CLAUDE.md, no `plugins/`. Every check fails with its fix and nothing crashes. Test in Task 1.
2. **Secrets in settings**: `env` and `mcpServers.*.env` values never appear in any output format. Test in Task 4.
3. **A broken settings file**: invalid JSON raises `RepeatOScopeError` naming the path; a UTF-8 BOM parses. Test in Task 1.
4. **A plugin with two cached versions**, or one installed but `false` in `enabledPlugins`: skills are counted once from `installPath`, and a disabled plugin's skills not at all. Test in Task 2.
5. **Project settings override user settings**: an `effortLevel: high` in `<cwd>/.claude/settings.local.json` fails the check even though the user file says `medium`, and the row names the local file. Test in Task 1.
