# audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `repeat-o-scope audit --format json` that measures waste, ties every wasted call to its evidence, groups and judges it, adds the settings checks, and feeds a `/repeat-o-scope` skill that turns it into themes and at most 4 fixes ranked by usage saved.

**Architecture:** `waste.measure` keeps each charged call's evidence next to its cost. A new `audit` module groups that evidence per kind with `cluster.rank`, attaches each group's `Tally`, judges groups through the first available judge (`judges.py`), and adds `doctor.diagnose` checks plus count-only `prompts`/`commands` findings. The skill does themes and the plan, and falls back to a Haiku subagent when no API judge is available.

**Tech Stack:** Python 3.12, `fire`, `typesafe-sdk`, `httpx`, `google-genai` (optional import), pytest.

**Spec:** `docs/superpowers/specs/2026-11-17-audit-design.md`

## Global Constraints

- Judge order: Jev, Gemini Decision 1 (`gemini-decision-1`), Clef, then Haiku as a skill subagent.
- Jev key: `TYPESAFE_API_KEY`, or `TYPESAFE_AI_API_KEY`. Gemini: `GEMINI_API_KEY`. Clef: `CLOUDFLARE_ACCOUNT_ID` + `CLOUDFLARE_API_KEY`.
- Available = env var set, client library imports, and a simple test call returns a non-error status.
- Clef endpoint: `POST https://api.cloudflare.com/client/v4/accounts/{CLOUDFLARE_ACCOUNT_ID}/ai/run/@cf/cloudflare/clef`, `Authorization: Bearer {CLOUDFLARE_API_KEY}`, body `{model, state, questions: {name: {type: choice|noul, instructions, criteria}}}`, answers in `result.answers` (`choice`, `confidence`, `noul`; no probabilities).
- Every external call has a timeout (reuse `judge._TIMEOUT_SECONDS = 30`).
- Evidence is redacted (`redaction.redact`) before it is grouped, judged or printed.
- `audit` calls `doctor.diagnose`, never copies its checks.
- `prompts` and `commands` findings carry no cost.
- The skill plans at most 4 fixes, ranked by share of usage saved.
- `compare` is out of scope; `audit` only writes the baseline.

## Review Focus

1. A judge whose env var is set but whose test call fails (bad key, 401, network down): fall through to the next judge, log which one failed and why, never crash the audit. Test in Task 2.
2. No judge available at all: the JSON says `"judge": null`, every group is still there, unjudged. Test in Task 3.
3. A charged call whose evidence is empty (tool error with empty content, Read without `file_path`): still counted in `measure` totals, grouped under a placeholder, not dropped. Test in Task 1.
4. A judge that answers fewer items than asked or errors mid-batch: raise `RepeatOScopeError` naming the judge, then fall through is NOT done mid-run (no mixed judges in one output). Test in Task 2.
5. Declined findings: `audit` drops them like the other reports, and `--all` brings them back. Test in Task 4.

### Task 3: The `audit` module

**Files:**
- Create: `src/repeat_o_scope/audit.py`
- Modify: `src/repeat_o_scope/findings.py` (`Finding.cost: Tally | None = None`, `Finding.share: float | None = None`; `kind` gains `refused_edit | reread | failed | denied | bare_yes`)
- Test: `tests/test_audit.py`

**Interfaces:**
- Consumes: `waste.measure`, `waste.Charge`, `judges.open_judge`, `judge.kinds_of_asks`, `judge.real_failures`, `doctor.diagnose`, `cluster.rank`, `findings.from_cluster`
- Produces:
  - `@dataclass(frozen=True) class Audit: measurement: Measurement; judge: str | None; findings: list[Finding]; checks: list[doctor.Check]`
  - `audit.run(*, claude_dir: Path, days: int, judge: bool, project_dir: Path, root: Path, since: datetime) -> Audit`

Steps inside `run`:
1. `measure`; group `charges` per kind: normalise evidence with `cluster.normalise`, `cluster.rank(..., min_size=1)` (every wasted call counts; groups of one are kept), one `Finding` per group with `cost` = summed `Tally` of its charges and `share` = cost weight / total weight.
2. If `judge`: `open_judge()`; `failed` groups → `real_failures` on the top example, drop groups judged noise (note it, as `fails` does); `bare_yes` groups → `kinds_of_asks`, set `label`. Other kinds are not judged.
3. Count-only findings from `prompts` and `commands` (reuse `Scope._clustered`'s logic by moving it to a module-level function `cli.clustered(...)` that `audit` imports — or into `audit` itself, whichever keeps `cli` thin).
4. `doctor.diagnose(claude_dir=..., project_dir=...)`.
5. Waste findings sorted by `share` descending, then prompts/commands by `total`.

### Task 5: The skill and README

**Files:**
- Modify: `src/repeat_o_scope/skill/SKILL.md`, `README.md`
- Test: `tests/test_skill.py`

New skill flow, replacing sections 2–3:
1. Run `repeat-o-scope audit --format json --jev`.
2. If `judge` is `null`: spawn one subagent with `model: "haiku"`, give it the `failed` groups' top examples and the `bare_yes` closing lines with the same questions as `judge._REAL` and `judge._ASK` (copy their text into the skill), and apply its answers the same way (drop noise, set labels). The subagent prompt says: "The Bash tool does not exist here. Use PowerShell for commands and Read/Grep/Glob for files."
3. Themes: merge findings across kinds that share one root cause; a theme's share is the sum of its findings' shares. Failing `checks` join the theme they explain (`idle_compact` with expired cache, `skills` with fixed context), or stand alone.
4. Pick at most 4 themes by share; prompts/commands findings compete on `total` only when fewer than 4 waste themes exist.
5. For a `skills` check: offer `disable-model-invocation: true` for the user's own skills in `~/.claude/skills`, `skillOverrides`/`enabledPlugins` for plugin skills; never edit the plugin cache.
6. Ask once, apply, decline (unchanged sections 5–6), and end with the headline share and the baseline path.
